How a computer finds questions with the same meaning

This page explains three tools. Each tool does one job. All the examples use one service: a bank of math practice questions for teachers.

Embedding modelChanges a text into a list of numbers. The numbers show the meaning. pgvectorKeeps the lists of numbers in Postgres. Finds the lists that are nearest. RabbitMQKeeps jobs in a line. Gives each job to a worker program.

The problem

A teacher types a search. The question bank has good matches. But the matches do not use the same words.

Search by

    Search by words looks for the same letters. Search by meaning needs two things: an embedding model and a place to compare the numbers. The next sections show both.

    Embedding model

    Official definition (embedding)

    “An embedding is a vector (list) of floating point numbers.”
    OpenAI, Vector embeddings guide

    In simple words

    An embedding model is a program. It reads a text and gives a list of numbers.

    The list is the embedding. Texts with the same meaning get similar lists.

    pgvector

    Official definition

    “Open-source vector similarity search for Postgres.”
    pgvector README, GitHub

    In simple words

    Postgres is a database. It keeps data in tables.

    pgvector is an extension for Postgres. It adds a vector column. It also finds the rows with the nearest vectors.

    The questions table

    Each row is one question. The embedding column keeps the 1,536 numbers. Click a search to sort the rows by meaning.

    idtextembeddingdistance
    
  
    <=> is the pgvector operator for cosine distance. It means “the distance between these two vectors”.
    

  
    Why an index makes search fast
    
  
    Without an index, Postgres compares the search with every row. An HNSW index connects near vectors like a map of roads. The search follows the roads and compares only a few rows.
    
  
    
    
    
    
    
  
    
  
    The HNSW search is approximate. It is very fast, but it can miss a match on some searches.
    

    



    
  
    RabbitMQ
    
  
    
    
    Official definition
    
      
    RabbitMQ is “a reliable and mature messaging and streaming broker.”
    
      rabbitmq.com
    
    
    In simple words
    
      
    A message broker is a program between other programs.
    
      
    One program sends a message. The broker keeps it in a queue. A worker program takes it when it is ready.
    
  
    

  
    Why the question bank needs a queue
    
  
    The embedding model needs about 1 second for each question. It also has a limit on requests. Five teachers click Save at the same time.
    
  
    
  
    
    
    Without a queue
    The API calls the model. Each teacher waits.
    
    
    With RabbitMQ
    The API puts a message in the queue and replies.
    
      
    Queue embed-questions
    
  
    

  
    The parts of RabbitMQ
    
  
    The API never puts a message directly into a queue. It sends the message to an exchange with a routing key. The exchange compares the key with each binding. It copies the message into each queue that matches.

    How RabbitMQ makes sure no job is lost
    
  
    The worker gets a message. RabbitMQ keeps a copy until the worker sends an acknowledgement (ack). If the worker stops first, the message goes back into the queue.
